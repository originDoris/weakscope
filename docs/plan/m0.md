## 2. 功能全景与进度（按开发顺序，7 个工作包）

### WP0 · 仓库与骨架（2h）

- [x] GitHub 建公开仓（定名；Apache-2.0 LICENSE）
- [x] `git clone` 到本地，`go mod init github.com/<你>/weakscope`
- [ ] `.gitignore`（AI 白名单）+ `README.md` 一句话定位 + `LEARNING.md` 第一行
- [ ] 首目录结构：`cmd/weakscope/` + `internal/` + `docs/plan/m0.md`（本文档）
- 需要认真理解：go.mod 的 module 路径语义（决定 import 前缀）——10 分钟读 go modules 中文简介即可

### WP1 · 探针第一版：单目标 TCP RTT（14h = 编码 8h + 精读 6h）

- [ ] `internal/probe/result.go`：结果结构体（ts/target/phase/rtt_ms/ok/err）+ json tag
- [ ] DNS 计时：`net.ResolveTCPAddr` 单独计时（phase=dns）
- [ ] TCP 连接计时：`net.Dialer` + `DialContext` 超时（phase=connect）
- [ ] JSONL 输出：`json.Marshal` 每行一个结果打到 stdout
- [ ] CLI 参数：先用标准库 `flag`（--target --interval --timeout；cobra 到 WP4 再换，第一周不碰魔法）
- [ ] 表驱动测试：result 结构的序列化；**为可测试性定义小接口 `Dialer`，测试里注入假实现**（这是 Go 关键一课：接口定义在使用方）
- 需要认真理解（精读级）：
  - LGWT（中文版）从 hello 到 structs/methods 章——这次是**边写边对读**，不是翻
  - `time.Now()`/`time.Since` 的单调时钟语义（自检题 8 的答案就在这里）
  - error 处理惯用法：`fmt.Errorf("%w", err)` 包装、`errors.Is`
  - 小林《图解网络》：TCP 建连章节（三次握手 = 1 RTT 的直觉来源）
- 浏览即可：encoding/json 文档、flag 包文档

### WP2 · 统计模块（10h = 编码+测试 6h + 精读 4h）

- [ ] `internal/stats/window.go`：定长滑窗（slice 实现即可，注意共享底层数组的坑）
- [ ] min / max / mean
- [ ] 百分位 p50/p95/p99（nearest-rank，直接排序）
- [ ] EWMA（RFC 6298 的 SRTT 公式，α=1/8，做成可传参）
- [ ] jitter（RFC 3550 §6.3.1：连续 RTT 差值的指数平均）
- [ ] 以上全部纯函数 + 表驱动测试（**M0 的 TDD 主战场，先写测试再写实现**）
- 需要认真理解：
  - **RFC 6298 §2 逐句精读**，SRTT/RTO 公式亲手推一遍——它就是 M1 trendline 的祖宗，这 2h 是全 M0 最值钱的精读
  - RFC 3550 §6.3.1 jitter 公式（为什么用差值不用绝对值——想想如果用 |D| 会怎样）
  - 小林《图解网络》超时重传（RTO）章节对照
  - sort 包、浮点比较的测试容忍度（delta 比较，不是 ==）
- 浏览即可：slice append 扩容规则（Effective Go / 100 Mistakes 对应节，写滑窗时自然会撞上）

### WP3 · 采样循环与多目标并发（12h = 编码 8h + 精读 4h）

- [ ] `time.Ticker` 采样循环 + `--duration` 自然停止
- [ ] `context.WithTimeout` 全局控制（Ctrl-C 也要能优雅退出：signal.NotifyContext）
- [ ] 多目标并发：`errgroup.WithContext`
- [ ] 结果汇聚：先用 channel 汇到单 collector（体会一次"通信共享内存"），再对比 mutex 版本
- [ ] 全程 `go test -race` + `go vet` 干净
- 需要认真理解：
  - **LGWT concurrency 章精读**（goroutine/channel/select/context 全在这一章）
  - Effective Go 的 concurrency 节
  - channel 关闭语义（谁关、重复关闭 panic）、typed nil 陷阱——自检题 1/3/4 的实战现场
  - ticker vs for+sleep 的漂移差异（自检题 5）
- 浏览即可：errgroup README（golang.org/x/sync）

### WP4 · 工程化升级（12h，其中 3h 为 AI 白名单块）

- [ ] 迁移到 cobra：`probe` 子命令 + `replay`/`diagnose`/`ask` 占位（骨架可 AI 生成，**你自己组装一遍**）
- [ ] slog JSON 日志（探针结果仍走 stdout JSONL，日志走 stderr slog——两回事，想清楚为什么）
- [ ] 终端表格输出（`probe --report table`：JSONL → 表格一层渲染）
- [ ] Makefile：lint / test / build / race 四目标 + golangci-lint
- [ ] **CI + goreleaser 合并一个 3h 块**：GitHub Actions（test+lint+race，linux/macOS × amd64/arm64）+ goreleaser snapshot 出 4 平台二进制（AI 白名单，但每行要能看懂）
- 需要认真理解：slog 官方博客中文译文（handler/level/结构化字段思想）；cobra 的 command 树模型（浏览）
- 浏览即可：golangci-lint 默认规则集

### WP5 · TCP_INFO · Linux（4h，弹性项，可滑到 M1 首周）

- [ ] `internal/probe/tcpinfo_linux.go`：syscall 取 tcp_info 的 rtt/rttvar
- [ ] build tag 隔离（`//go:build linux`），Docker/OrbStack 里跑 Linux 验证
- [ ] 文档写明 macOS 无此接口的平台差异
- 需要认真理解：build tag 机制、`syscall` 包使用分寸（能用 golang.org/x/sys 就不用 syscall）

### WP6 · 基准、README、发布、博文①（9h）

- [ ] `testing.B` 给 stats 热点函数做基准 + `-benchmem`，跑一次 pprof 看火焰图（不追求优化，只为见过）
- [ ] README v0：定位一句话 + 快速上手 + 架构小图 + badge（CI 状态）
- [ ] `git tag v0.1.0` + goreleaser 出第一个 GitHub Release
- [ ] **博文①成稿发布（4h）**，大纲见 §5
- 需要认真理解：Go 博客《Profiling Go Programs》中文译文（bench/pprof 惯用法）
